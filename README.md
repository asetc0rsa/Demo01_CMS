Архитектура
Проект построен по принципу разделения ответственности и состоит из двух слоёв:
ACM.BL (Business Layer)
Слой бизнес-логики. Содержит:
Предметные классы (Customer, Product, Order, OrderItem, Address)
Контракты репозиториев (интерфейсы ICustomerRepository, IProductRepository и т.д.)
Классы проверяют свои данные через метод Validate(), но не выполняют чтение и сохранение — это делает слой DAL через интерфейсы.
ACM.DAL (Data Access Layer)
Слой доступа к данным. Содержит:
In-Memory реализации репозиториев (InMemoryCustomerRepository, InMemoryProductRepository и т.д.)
Хранят копии объектов в памяти и назначают идентификаторы при первом сохранении. Зависит от ACM.BL; предметные классы не зависят от слоя доступа к данным.

Ключевые особенности
Валидация данных — каждый класс имеет метод Validate(), проверяющий обязательные поля.
Генерация ID — при первом сохранении (Id == 0) репозиторий автоматически назначает уникальный идентификатор.
In-Memory хранилище — данные доступны только через тот же экземпляр репозитория и исчезают при завершении процесса (учебная реализация).
Принцип инверсии зависимостей — ACM.BL не знает о ACM.DAL, что позволяет легко заменить In-Memory репозитории на работу с реальной базой данных.
